# 总设置

*好的框架需要统一的配置入口，Setting 就是这个入口。*

Setting 类集中管理 Yoyo Core 框架的全局配置，通过修改这些静态字段，可以控制框架的各个行为。

## 配置项说明

**IsOpenLayOut**

```csharp
public static bool IsOpenLayOut = true;
```

**作用**：控制是否开启层级整理功能。

**影响范围**：
- PoolMgr：对象池会创建层级结构管理对象
- BaseMgr_Mono：自动创建的 GameObject 会放在根节点

**开启时**：
```
Scene
├── Pool
│   ├── BulletPool
│   └── EnemyPool
├── MonoMgr
├── EventMgr
└── ...
```

**关闭时**：对象直接创建在场景根节点，没有层级结构。

**建议**：开发时开启，方便调试；发布时可关闭以减少层级开销。

**IntervalTime**

```csharp
public static float IntervalTime = 0.05f;
```

**作用**：TimerMgr 的计时器更新间隔。

**影响范围**：
- TimerMgr 的所有计时器

**说明**：
- 值越小，计时精度越高，但 CPU 开销越大
- 值越大，性能越好，但计时精度降低
- 默认 0.05 秒（20 FPS 更新频率）

**调整建议**：
- 需要精确计时（如音乐游戏）：0.01f ~ 0.02f
- 普通游戏：0.05f
- 对计时精度要求不高：0.1f

**isDebugMode**

```csharp
public static bool isDebugMode = true;
```

**作用**：控制是否开启调试模式。

**影响范围**：
- DebugTool：控制日志输出
- 其他可能使用此标志的调试功能

**说明**：
- true：输出所有 Debug 日志
- false：屏蔽所有 Debug 日志

**重要**：发布前务必将此值设为 false！

## 使用方法

**开发阶段配置**

```csharp
public class Setting
{
    public static bool IsOpenLayOut = true;      // 开启层级整理，方便调试
    public static float IntervalTime = 0.05f;    // 默认更新频率
    public static bool isDebugMode = true;       // 开启日志输出
}
```

**发布阶段配置**

```csharp
public class Setting
{
    public static bool IsOpenLayOut = false;     // 关闭层级整理
    public static float IntervalTime = 0.05f;    // 保持默认
    public static bool isDebugMode = false;      // 关闭日志输出！
}
```

**运行时修改**

某些配置可以在运行时动态修改：

```csharp
// 关闭层级整理（不再创建新的层级结构）
Setting.IsOpenLayOut = false;

// 调整计时器精度
Setting.IntervalTime = 0.02f;
TimerMgr.Instance.Stop();
TimerMgr.Instance.Start();  // 需要重启计时器才能生效

// 关闭调试模式
Setting.isDebugMode = false;
```

## 扩展配置

你可以根据需要扩展 Setting 类：

```csharp
public class Setting
{
    // 原有配置
    public static bool IsOpenLayOut = true;
    public static float IntervalTime = 0.05f;
    public static bool isDebugMode = true;

    // 新增：游戏配置
    public static float GameVolume = 1.0f;
    public static int TargetFrameRate = 60;
    public static bool ShowFPS = true;

    // 新增：网络配置
    public static string ServerAddress = "127.0.0.1";
    public static int ServerPort = 8080;
    public static float NetworkTimeout = 10f;

    // 新增：存档配置
    public static string SaveFileName = "save.dat";
    public static bool AutoSave = true;
    public static float AutoSaveInterval = 300f;
}
```

## 配置持久化

如果需要将配置保存到本地，可以添加读写方法：

```csharp
public class Setting
{
    // ... 配置项

    public static void Save()
    {
        PlayerPrefs.SetInt("IsOpenLayOut", IsOpenLayOut ? 1 : 0);
        PlayerPrefs.SetFloat("IntervalTime", IntervalTime);
        PlayerPrefs.SetInt("isDebugMode", isDebugMode ? 1 : 0);
        PlayerPrefs.Save();
    }

    public static void Load()
    {
        IsOpenLayOut = PlayerPrefs.GetInt("IsOpenLayOut", 1) == 1;
        IntervalTime = PlayerPrefs.GetFloat("IntervalTime", 0.05f);
        isDebugMode = PlayerPrefs.GetInt("isDebugMode", 1) == 1;
    }
}
```

## 注意事项

**1. 静态字段的特性**

Setting 使用静态字段，这意味着：
- 全局唯一，任何地方修改都会影响全部
- 游戏重启后恢复默认值（除非做持久化）
- 多线程访问需要考虑线程安全

**2. 修改时机**

某些配置修改后需要重启相关系统才能生效：

```csharp
// 修改 IntervalTime 后需要重启 TimerMgr
Setting.IntervalTime = 0.02f;
TimerMgr.Instance.Stop();
TimerMgr.Instance.Start();
```

**3. 发布检查清单**

发布前检查 Setting 中的以下项目：
- isDebugMode = false
- IsOpenLayOut 根据需求设置
- IntervalTime 合适
- 其他自定义配置正确

## 技术地位和意义

Setting 是框架的「配置中心」。它将分散的配置集中管理，让框架的行为可以通过统一的入口进行控制。

*好的配置设计，能让框架适应不同的项目需求，而不需要修改代码。*
