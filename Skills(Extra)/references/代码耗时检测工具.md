# 代码耗时检测工具

*优化代码之前，你得先知道哪里慢。CustomTimerTool 就是那个告诉你「哪里慢」的工具。*

CustomTimerTool 提供了一个简单的代码段耗时测量功能，基于 IDisposable 接口实现，使用非常方便。

## 诞生背景

性能优化是游戏开发中永恒的话题。但在优化之前，我们需要知道：

1. 哪段代码是性能瓶颈？
2. 优化后到底快了多少？

传统的计时方式：

```csharp
float startTime = Time.realtimeSinceStartup;

// 要测量的代码
DoSomething();

float endTime = Time.realtimeSinceStartup;
Debug.Log($"耗时: {(endTime - startTime) * 1000}ms");
```

这种方式的问题是：
- 代码侵入性强
- 如果有多个 return 分支，计时逻辑会很复杂
- 忘记写结束计时会导致错误

CustomTimerTool 使用 using 语句和 IDisposable，让计时更加优雅。

## 核心功能

**基本使用**

```csharp
using (new CustomTimerTool("某操作"))
{
    // 要测量的代码
    DoSomething();
}
// 离开 using 块时自动输出耗时
```

控制台输出：
```
某操作: 15.23ms
```

## 使用方法

**测量函数耗时**

```csharp
void HeavyOperation()
{
    using (new CustomTimerTool("HeavyOperation"))
    {
        for (int i = 0; i < 10000; i++)
        {
            CalculateSomething();
        }
    }
}
```

**测量代码块耗时**

```csharp
void Update()
{
    using (new CustomTimerTool("物理更新"))
    {
        UpdatePhysics();
    }

    using (new CustomTimerTool("逻辑更新"))
    {
        UpdateLogic();
    }

    using (new CustomTimerTool("渲染更新"))
    {
        UpdateRender();
    }
}
```

**嵌套测量**

```csharp
void ComplexOperation()
{
    using (new CustomTimerTool("总操作"))
    {
        using (new CustomTimerTool("步骤1"))
        {
            Step1();
        }

        using (new CustomTimerTool("步骤2"))
        {
            Step2();
        }

        using (new CustomTimerTool("步骤3"))
        {
            Step3();
        }
    }
}
```

输出：
```
步骤1: 5.12ms
步骤2: 10.45ms
步骤3: 3.21ms
总操作: 18.78ms
```

**条件测量**

```csharp
void SomeFunction()
{
    if (Setting.isDebugMode)
    {
        using (new CustomTimerTool("SomeFunction"))
        {
            // 实际代码
            DoWork();
        }
    }
    else
    {
        DoWork();
    }
}
```

## 技术实现

```csharp
public class CustomTimerTool : IDisposable
{
    private string Name;
    private float StartTime;

    public CustomTimerTool(string name)
    {
        Name = name;
        StartTime = Time.realtimeSinceStartup;
    }

    public void Dispose()
    {
        float duration = (Time.realtimeSinceStartup - StartTime) * 1000;
        Debug.Log($"{Name}: {duration:F2}ms");
    }
}
```

## 注意事项

1. **使用 Time.realtimeSinceStartup**：不受 Time.timeScale 影响，测量更准确

2. **只在调试时使用**：发布版本应该移除计时代码，或根据条件编译

3. **避免过度测量**：过多的测量会影响性能，只测量关键代码段

4. **注意 GC**：频繁创建 CustomTimerTool 对象会产生垃圾，在性能敏感的场景要注意
