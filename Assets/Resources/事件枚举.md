<b><size=20>事件枚举</size></b>

<i>事件系统是框架的神经系统，而 EventType 就是这个系统的「信号编码」。</i>

EventEnums 定义了框架中使用的事件类型枚举，是事件中心（EventMgr）的基础。

<b><size=16>核心概念</size></b>

EventType 是一个枚举类型，用于标识不同的事件：

public enum EventType
{
    BaseEvent,
    Move
}

每个枚举值代表一种特定的事件类型，用于事件的订阅和触发。

<b><size=16>使用方法</size></b>

<b>定义新事件</b>

在 EventEnums.cs 中添加新的事件类型：

public enum EventType
{
    BaseEvent,
    Move,

    // 游戏系统事件
    GameStart,
    GamePause,
    GameResume,
    GameOver,

    // 玩家相关事件
    PlayerHPChange,
    PlayerMPChange,
    PlayerLevelUp,
    PlayerDie,

    // 输入事件
    Jump,
    Fire,
    Skill1,
    Skill2,

    // UI 事件
    OpenMenu,
    CloseMenu,
    ShowDialog,
    HideDialog,

    // 场景事件
    SceneLoadStart,
    SceneLoadComplete,

    // 自定义事件...
    MyCustomEvent
}

<b>订阅事件</b>

void Start()
{
    // 订阅玩家血量变化事件
    EventMgr.Instance.AddEventListener<int>(EventType.PlayerHPChange, OnHPChange);

    // 订阅游戏开始事件
    EventMgr.Instance.AddEventListener(EventType.GameStart, OnGameStart);
}

void OnHPChange(int hp)
{
    Debug.Log($"当前血量: {hp}");
}

void OnGameStart()
{
    Debug.Log("游戏开始！");
}

<b>触发事件</b>

void TakeDamage(int damage)
{
    hp -= damage;
    // 触发血量变化事件
    EventMgr.Instance.EventTrigger(EventType.PlayerHPChange, hp);

    if (hp <= 0)
    {
        // 触发玩家死亡事件
        EventMgr.Instance.EventTrigger(EventType.PlayerDie);
    }
}

<b><size=16>事件命名规范</size></b>

为了保持代码的可读性和可维护性，建议遵循以下命名规范：

<size=13><b>1. 使用有意义的名称</b>

// 好的命名
PlayerHPChange,
EnemySpawn,
ItemPickup

// 不好的命名
Event1,
Event2,
DoSomething

<b>2. 使用动词+名词的结构</b>

// 状态变化
PlayerHPChange,     // 玩家血量变化
EnemySpawn,         // 敌人生成
ItemPickup,         // 物品拾取

// 动作指令
Jump,               // 跳跃
Fire,               // 开火
OpenMenu,           // 打开菜单

<b>3. 按模块分组</b>

public enum EventType
{
    //========== 框架事件 ==========
    BaseEvent,

    //========== 输入事件 ==========
    Move,
    Jump,
    Fire,

    //========== 游戏系统事件 ==========
    GameStart,
    GamePause,
    GameOver,

    //========== 玩家事件 ==========
    PlayerHPChange,
    PlayerMPChange,
    PlayerLevelUp,
    PlayerDie,

    //========== 敌人事件 ==========
    EnemySpawn,
    EnemyDie,
    EnemyAlert,

    //========== UI 事件 ==========
    OpenMenu,
    CloseMenu,
    ShowDialog,
    HideDialog,
    ButtonClick,

    //========== 场景事件 ==========
    SceneLoadStart,
    SceneLoadComplete,
    SceneUnload
}

<b>4. 避免过于具体的名称</b>

// 过于具体，复用性差
PlayerRedPotionPickup,

// 更通用的命名
ItemPickup,  // 通过参数传递物品类型</size>

<b><size=16>事件参数设计</size></b>

事件可以带参数，参数的设计也很重要：

<b>简单事件（无参数）</b>

// 不需要额外信息的事件
EventMgr.Instance.EventTrigger(EventType.GameStart);
EventMgr.Instance.EventTrigger(EventType.Jump);

<b>带一个参数</b>

// 血量变化，只需要传递当前血量
EventMgr.Instance.EventTrigger(EventType.PlayerHPChange, currentHP);

// 场景加载完成，传递场景名称
EventMgr.Instance.EventTrigger(EventType.SceneLoadComplete, "Level2");

<b>带多个参数</b>

如果需要传递多个参数，使用类或结构体封装：

public struct DamageInfo
{
    public int Damage;
    public Vector3 HitPosition;
    public GameObject Attacker;
}

// 触发伤害事件
DamageInfo info = new DamageInfo
{
    Damage = 100,
    HitPosition = transform.position,
    Attacker = player
};
EventMgr.Instance.EventTrigger(EventType.TakeDamage, info);

<b><size=16>完整示例</size></b>

<b>玩家系统事件</b>

public enum EventType
{
    // 属性变化
    PlayerHPChange,     // int: 当前血量
    PlayerMPChange,     // int: 当前蓝量
    PlayerLevelUp,      // int: 新等级

    // 状态变化
    PlayerSpawn,        // Vector3: 出生位置
    PlayerDie,          // 无参数
    PlayerRevive,       // Vector3: 复活位置

    // 交互
    PlayerPickupItem,   // ItemData: 物品数据
    PlayerEquipItem,    // EquipmentData: 装备数据
}

<b>UI 系统事件</b>

public enum EventType
{
    // 菜单
    OpenMenu,           // string: 菜单名称
    CloseMenu,          // string: 菜单名称
    MenuOpened,         // string: 菜单名称（通知菜单已打开）
    MenuClosed,         // string: 菜单名称（通知菜单已关闭）

    // 对话框
    ShowDialog,         // DialogData: 对话框数据
    HideDialog,         // 无参数
    DialogButtonClick,  // int: 按钮索引

    // 提示
    ShowToast,          // string: 提示文本
    ShowNotification,   // NotificationData: 通知数据
}

<b><size=16>注意事项</size></b>

<size=13><b>1. 事件数量控制</b>

事件类型不宜过多，过多的事件会增加维护难度：

// 不推荐：为每个按钮都定义事件
Button1Click,
Button2Click,
Button3Click,
// ...

// 推荐：使用通用事件+参数
ButtonClick,  // 参数传递按钮ID

<b>2. 事件命名一致性</b>

保持命名风格一致：

// 一致性示例
PlayerHPChange,     // 名词+动词
EnemySpawn,         // 名词+动词
ItemPickup,         // 名词+动词

// 避免混用
PlayerHPChanged,    // 过去式
EnemySpawning,      // 进行时
ItemPickUp          // 动词+介词

<b>3. 文档注释</b>

为复杂事件添加注释：

public enum EventType
{
    /// <summary>
    /// 玩家血量变化事件
    /// 参数：int currentHP - 当前血量百分比（0-100）
    /// </summary>
    PlayerHPChange,

    /// <summary>
    /// 场景加载完成事件
    /// 参数：string sceneName - 加载完成的场景名称
    /// </summary>
    SceneLoadComplete
}</c></size>

<b><size=16>与 InputMgr 的配合</size></b>

EventType 经常与 InputMgr 配合使用：

// 在 EventEnums.cs 中定义输入相关事件
public enum EventType
{
    MoveLeft,
    MoveRight,
    Jump,
    Fire,
    Skill1,
    Skill2
}

// 在 InputMgr 中绑定输入
InputMgr.Instance.AddKeyBoardInfo(EventType.Jump, KeyCode.Space, InputInfo.E_InputType.Down);
InputMgr.Instance.AddKeyBoardInfo(EventType.Fire, KeyCode.Mouse0, InputInfo.E_InputType.Down);

// 在其他地方订阅事件
EventMgr.Instance.AddEventListener(EventType.Jump, () => player.Jump());
EventMgr.Instance.AddEventListener(EventType.Fire, () => player.Fire());

<b><size=16>技术地位和意义</size></b>

EventType 是框架事件系统的「词汇表」。良好设计的事件类型能让代码更易读、更易维护，也是团队协作的基础。

<i>事件命名就像给变量命名一样，看似简单，却直接影响代码的可读性。花点时间设计好事件体系，后期维护会轻松很多。</i>
