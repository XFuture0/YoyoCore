<b><size=20>事件中心</size></b>

<i>如果代码之间直接对话，那就像一群人挤在一个房间里互相喊话。事件中心就是那个「传话筒」。</i>

在 Unity 开发中，模块间的通信一直是个让人头疼的问题。直接引用会导致耦合度飙升，而 Unity 的 SendMessage 又缺乏类型安全。EventMgr 提供了一个类型安全、松耦合的事件系统。

<b><size=16>诞生背景</size></b>

假设你有两个模块：Player（玩家）和 UI（界面）。当玩家血量变化时，UI 需要更新血条显示。

<b>直接引用的方式</b>：

public class Player
{
    public UIMgr uiMgr; // 直接引用，耦合度高

    void TakeDamage()
    {
        hp -= 10;
        uiMgr.UpdateHP(hp); // 直接调用
    }
}

这种方式的问题是：Player 必须知道 UIMgr 的存在，而且如果以后要添加更多响应者（如音效、特效），Player 代码就要修改。

<b>事件中心的方式</b>：

public class Player
{
    void TakeDamage()
    {
        hp -= 10;
        EventMgr.Instance.EventTrigger(EventType.PlayerHPChange, hp);
    }
}

public class UIMgr
{
    void Start()
    {
        EventMgr.Instance.AddEventListener&lt;int&gt;(EventType.PlayerHPChange, UpdateHP);
    }
}

Player 不需要知道谁在监听，只需要「广播」事件即可。

<b><size=16>核心功能</size></b>

EventMgr 提供了两套 API：带参数的事件和无参数的事件。

<b>带参数的事件</b>

适用于需要传递数据的场景：

// 订阅事件
EventMgr.Instance.AddEventListener&lt;int&gt;(EventType.PlayerHPChange, OnHPChange);

// 触发事件
EventMgr.Instance.EventTrigger(EventType.PlayerHPChange, 100);

// 取消订阅
EventMgr.Instance.RemoveEventListener&lt;int&gt;(EventType.PlayerHPChange, OnHPChange);

void OnHPChange(int hp)
{
    Debug.Log($"当前血量: {hp}");
}

<b>无参数的事件</b>

适用于只需要「通知」的场景：

// 订阅
EventMgr.Instance.AddEventListener(EventType.GameStart, OnGameStart);

// 触发
EventMgr.Instance.EventTrigger(EventType.GameStart);

// 取消订阅
EventMgr.Instance.RemoveEventListener(EventType.GameStart, OnGameStart);

<b><size=16>使用方法</size></b>

<b>定义事件类型</b>

首先，你需要在 EventEnums.cs 中定义事件类型：

public enum EventType
{
    BaseEvent,
    PlayerHPChange,
    GameStart,
    GameOver,
    // ...
}

<b>订阅与触发</b>

public class Example : MonoBehaviour
{
    void Start()
    {
        // 订阅事件
        EventMgr.Instance.AddEventListener&lt;int&gt;(EventType.PlayerHPChange, HandleHPChange);
        EventMgr.Instance.AddEventListener(EventType.GameStart, HandleGameStart);
    }

    void OnDestroy()
    {
        // 必须取消订阅！
        EventMgr.Instance.RemoveEventListener&lt;int&gt;(EventType.PlayerHPChange, HandleHPChange);
        EventMgr.Instance.RemoveEventListener(EventType.GameStart, HandleGameStart);
    }

    void HandleHPChange(int hp)
    {
        Debug.Log($"血量变化: {hp}");
    }

    void HandleGameStart()
    {
        Debug.Log("游戏开始！");
    }
}

<b><size=16>技术实现</size></b>

EventMgr 内部使用字典存储事件：

private Dictionary&lt;EventType, EventInfoBase&gt; eventDic = new Dictionary&lt;EventType, EventInfoBase&gt;();

通过泛型类 EventInfo&lt;T&gt; 和 EventInfo 分别处理带参数和无参数的情况。

<b><size=16>注意事项</size></b>

<b>1. 必须取消订阅</b>

这是最常见的问题。如果对象被销毁但没有取消订阅，事件回调会尝试访问已销毁的对象，导致错误。

void OnDestroy()
{
    EventMgr.Instance.RemoveEventListener&lt;int&gt;(EventType.PlayerHPChange, HandleHPChange);
}

<b>2. 事件类型匹配</b>

订阅和触发时必须使用相同的 EventType，参数类型也要匹配。

<b>3. 清空事件</b>

在场景切换或游戏结束时，可能需要清空所有事件：

// 清空特定事件的所有订阅
EventMgr.Instance.Clear(EventType.PlayerHPChange);

// 清空所有事件
EventMgr.Instance.Clear();

<b><size=16>适用场景</size></b>

<b>场景：玩家血量变化通知 UI</b>
是否适合使用事件中心：适合

<b>场景：游戏开始/结束广播</b>
是否适合使用事件中心：适合

<b>场景：每帧的位置同步</b>
是否适合使用事件中心：不适合（性能考虑）

<b>场景：两个需要频繁通信的模块</b>
是否适合使用事件中心：不适合（直接引用更高效）

<b><size=16>与其他通信方式的对比</size></b>

<b>方式：直接引用</b>
耦合度：高
类型安全：是
适用场景：紧密关联的模块

<b>方式：事件中心</b>
耦合度：低
类型安全：是
适用场景：松耦合的模块通信

<b>方式：UnityEvents</b>
耦合度：中
类型安全：是
适用场景：Inspector 配置

<b>方式：SendMessage</b>
耦合度：低
类型安全：否
适用场景：快速原型（不推荐）

<b><size=16>技术地位和意义</size></b>

事件中心是游戏架构中「观察者模式」的典型应用。它实现了模块间的解耦，让代码更加灵活和可维护。在 Yoyo Core 框架中，它是实现模块通信的核心组件。

<i>记住：好的架构不是让代码之间「不说话」，而是让它们通过合适的方式「说话」。</i>
