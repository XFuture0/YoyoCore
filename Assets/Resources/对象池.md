<b><size=20>对象池</size></b>

<i>Instantiate 和 Destroy 是性能杀手？对象池说：「放着我来」。</i>

在游戏开发中，频繁地创建和销毁对象（如子弹、敌人、特效）会导致严重的性能问题。对象池模式通过复用对象来解决这个问题。

<b><size=16>诞生背景</size></b>

想象一个射击游戏，玩家每秒发射 10 发子弹，每发子弹存在 2 秒。传统的做法是：

// 发射时创建
GameObject bullet = Instantiate(bulletPrefab);

// 2秒后销毁
Destroy(bullet);

这样做的问题是：
1. <b>内存分配</b>：频繁的 Instantiate 导致频繁的内存分配
2. <b>垃圾回收</b>：频繁的 Destroy 产生大量垃圾，触发 GC 导致卡顿
3. <b>CPU 开销</b>：Instantiate 和 Destroy 本身就有不小的 CPU 开销

对象池的核心思想是：<b>预先创建一批对象，需要时「取出」，用完「归还」，而不是销毁。</b>

<b><size=16>核心概念</size></b>

PoolMgr 使用 PoolData 来管理每种类型的对象池：

public class PoolData
{
    private Stack&lt;GameObject&gt; dataStack = new Stack&lt;GameObject&gt;();
    private GameObject rootObj;      // 对象池的根节点（用于层级管理）
    private GameObject SaveObj;      // 模板对象
    private int MaxCount;            // 最大容量
}

<b><size=16>使用方法</size></b>

<b>初始化对象池</b>

在使用对象池之前，需要先初始化：

// 初始化子弹对象池，最大容量 100
PoolMgr.Instance.InitPool(bulletPrefab, 100);

<b>获取对象</b>

GameObject bullet = PoolMgr.Instance.PopObj("Bullet");

<b>归还对象</b>

PoolMgr.Instance.PushObj(bullet);

<b><size=16>完整示例</size></b>

public class Gun : MonoBehaviour
{
    public GameObject bulletPrefab;

    void Start()
    {
        // 初始化对象池
        PoolMgr.Instance.InitPool(bulletPrefab, 50);
    }

    void Fire()
    {
        // 从对象池获取子弹
        GameObject bullet = PoolMgr.Instance.PopObj(bulletPrefab.name);
        bullet.transform.position = firePoint.position;
        bullet.transform.rotation = firePoint.rotation;

        // 启动子弹逻辑
        bullet.GetComponent&lt;Bullet&gt;().Launch();
    }
}

public class Bullet : MonoBehaviour
{
    void OnTriggerEnter(Collider other)
    {
        // 命中后归还对象池
        PoolMgr.Instance.PushObj(gameObject);
    }
}

<b><size=16>技术细节</size></b>

<b>对象池的自动扩容</b>

当对象池为空时，如果需要获取对象，PoolMgr 会自动创建新的实例。

<b>容量限制</b>

对象池有最大容量限制，超过容量的对象会被销毁并输出警告。

<b>层级管理</b>

如果开启了 Setting.IsOpenLayOut，对象池会自动创建层级结构管理对象。

<b><size=16>注意事项</size></b>

<b>1. 对象状态重置</b>

从对象池取出的对象可能带有之前的状态，使用前需要重置：

public class Bullet : MonoBehaviour
{
    public void OnSpawn()
    {
        // 重置状态
        hp = maxHP;
        velocity = Vector3.zero;
        // ...
    }
}

<b>2. 命名一致性</b>

PopObj 方法通过对象名称来获取，确保预制体的名称和调用时一致。

<b>3. 不要重复初始化</b>

同一个预制体不要重复初始化对象池，否则会输出警告。

<b>4. 清理对象池</b>

场景切换时可能需要清理对象池：

PoolMgr.Instance.ClearPool();

<b><size=16>适用场景</size></b>

<b>场景：频繁发射的子弹</b>
是否适合使用对象池：强烈推荐

<b>场景：不断生成的敌人</b>
是否适合使用对象池：强烈推荐

<b>场景：重复播放的特效</b>
是否适合使用对象池：推荐

<b>场景：玩家角色</b>
是否适合使用对象池：不适合（通常只有一个）

<b>场景：场景中的静态物体</b>
是否适合使用对象池：不适合

<b><size=16>性能对比</size></b>

<b>操作：内存分配</b>
Instantiate/Destroy：每次都有
对象池：初始化时一次

<b>操作：GC 压力</b>
Instantiate/Destroy：高
对象池：几乎为零

<b>操作：CPU 开销</b>
Instantiate/Destroy：高
对象池：极低（Stack 操作）

<b>操作：首次创建延迟</b>
Instantiate/Destroy：有
对象池：有（可预加载避免）

<b><size=16>技术地位和意义</size></b>

对象池是游戏开发中最常用的性能优化手段之一。PoolMgr 提供了一个开箱即用的对象池实现，让开发者可以轻松获得性能提升。

<i>记住：优化不是 Premature Optimization，对象池这种「基础优化」应该在项目早期就引入。</i>
