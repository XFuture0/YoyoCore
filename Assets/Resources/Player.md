# 2025年绘蓝杯游戏方向赛题(B组)

### 游戏开发

> 赛题要求:
>
> + 引擎: 必须使用Unity引擎开发
> + 语言: C#
> + 游戏完整度: 包括但不限于 <b>游戏开始界面,游戏核心玩法完善,游戏流程完整,游戏结束界面</b>
> + 素材要求: 游戏素材(音乐,图片等素材)可以使用网上的素材,也可以选择自己制作素材
> + 代码要求: 游戏中脚本代码尽可能独立实现,禁止大量使用网上代码
> + 插件要求: 必要时可使用插件,插件使用前请询问科协游戏方向相关人员
> + 比赛要求: 题目一为**限制性题目**，题目二，三为**开放性题目**,<b>提倡发挥想象力实现更多其他拓展项中未涉及的创意功能</b>

### 题目一: 横版跳跃2D游戏

#### 基本

- **完整的游戏流程**：游戏开始界面，游戏核心玩法完善，游戏流程完整，游戏结束界面
- 无明显**bug**
- 基础内容需**全部实现**，而后可以根据其他题目的基础或进阶内容进行拓展

#### 基础内容

1. **主角:** 
   - 移动、跳跃(二连跳)、攻击、冲刺、死亡等，要求动画正常，衔接流畅，不同状态下对应的动画转换基本无BUG。
   - 视角移动流畅无卡顿。
   - 有二段攻击，在每段攻击停止后若无下一段攻击则恢复初始状态
2. **敌人:**
   - 两种或更多的场景敌人
   - 要求每个敌人攻击方式或多或少有不同的地方，不能只是Sprite不一样
   - 一个木桩式敌人，能在场景中**自动生成**，无攻击状态，但有血量显示，并能在死亡后自动消失。
3. **Boss**：
   * 制作一个利用状态机做切换的Boss
   * Boss应有走路、释放技能和攻击的动画
   * Boss至少有静止，追踪玩家，释放技能三个状态
   * Boss要有一个大血条显示
4. **UI界面:** 
   - 制作开始与结束的UI界面;
   - 制作主角的血条和冲刺精力条
   - 制作一个暂停游戏UI菜单，可以使得游戏暂停，然后有回到主菜单、打开设置、返回游戏三个选项
   - 敌人头顶血条
5. **游戏场景:** 
   - 搭建完整的关卡地图;
   - 流程的场景切换
   - 场景切换时要使用淡入淡出效果
   - 至少制作三个可以游玩的场景<u>*(只含新手教程的小场景除外)*</u>

6. **摄像机**：
   * 使用 Cinemachine 制作相机跟随玩家
   * 玩家受伤、玩家攻击到敌人时镜头抖动
   * 场景切换时摄像机的范围也要随着场景更改
7. **音效：**
   - 添加玩家脚步声
   - 添加玩家攻击音效
   - 添加怪物死亡音效
8. **NPC**：
   * 一个可以进行对话的NPC，靠近后按下互动键冒出对话框
   * 对话框中需要有说话对象的头像和说话的内容
   * 对话框中的文字是一个一个字进行输出，而不是整行
   * 按下互动键后可以快速输出整行对话
9. **灯光**：
   * 使用URP构建自己的项目
   * 在场景中加入光源，可以是场景中的灯，也可以是玩家本身发光
10. **场景道具**：
    * 制作一个血包道具放置在场景中或者由怪物掉落，玩家靠近后可回血
    * 制作一个场景陷阱，玩家触碰到后会扣除血量
11. **新手引导:** 
    - 新手教程(可以是小界面引导,可以放在界面UI中作为帮助组件等,方式不限)
12. **管理器**：
    * 制作一个SceneChangeManager脚本作为单例模式，并且保证这个脚本在场景切换时不被清除



### 题目二: 2D游戏

<u>视角不限，题材不限</u>

#### 基本

- **完整的游戏流程**：游戏开始界面，游戏核心玩法完善，游戏流程完整，游戏结束界面
- 无明显**bug**
- 以下内容均为**可选项**，**不必在游戏中全部体现。**
- 进阶部分为有兴趣的**自行选择学习**

#### 基础游戏内容

* **新手引导**：可以是游戏流程内的引导，可以放在界面UI中作为帮助组件等,方式不限**（荐）**
* **更加多样化的主角动画**：移动、跳跃(二连跳)、滑行、翻滚、冲刺、爬墙、死亡等，要求动画正常，衔接流畅，不同状态下对应的动画转换基本无BUG。
* **更多样化的敌人**：两种或更多的敌人，要求每个敌人(攻击方式/状态切换)或多或少有不同的地方
* **设计一个游戏Boss**：用状态机制作一个boss来增加难度
* **完善的游戏UI**：制作开始与结束的UI界面，可以进行游戏暂停,可以设计一个设置的选项来做音量调整**（荐）**
* **相机系统**：使用 Cinemachine 制作可切换视角的相机，制作受击震动，摄像机弱引导等优化游戏表现的功能
* **更完整的游戏音效**：添加敌人音效，攻击音效，脚步声，受击音效，背景音效等等
* **完整的游戏关卡地图**：搭建完整的关卡地图**（荐）**
* **设计模式**：利用单例模式 / 观察者模式 等设计模式来组织代码结构**（荐）**
* **过场动画**：使用 TimeLine 来制作过场动画 / 局内游戏动画等动画效果
* **渲染管线**：使用 URP 代替 unity 传统渲染管线(若本身项目是非URP可以去学习下怎么把自己的项目升级到URP)**（荐）**

#### 进阶内容

* **数据存储**：用 PlayerPrefs / Json / ScriptableObject 等方式进行数据或存档的存储功能**（荐）**
* **性能优化**：利用对象池来优化需要大量重复生成的单一实体实例；打包图集来减少draw call，提升渲染效率；少用update / fixedupdate 来减少每帧对逻辑的调用次数......
* **手柄适配**：优化手柄端的输入死区，做到各个厂家之间的手柄适配，制作手柄马达分区震动效果
* **动画优化**：减少 Animator Controller 的状态数量，使用简单的 BlendTree 来控制动画播放
* **更好的UI** ：制作 UI 动效，利用 unity 内置的 UI 组件做到更好的组合、展示 UI （如 ScrollView、Mask 等等）；
* **粒子特效**：使用 unity 内置粒子特效来优化场景或游戏表现，例如攻击特效，受伤特效，死亡特效，场景元素特效：火焰，灯光，岩浆，传送门...
* **地图背景**：制作视差效果，可互动的背景元素，制作更有氛围的灯光效果
* **装扮系统**：可以在游戏进行时更换主角的皮肤样式
* **骨骼系统**：将静态图片动画转换为骨骼动画，处理骨骼结构以及骨骼运动，可以结合 IK 来实现更复杂的动作
* **技能系统**：给你的角色添加一个技能树进行加点，解锁更多不一样的技能
* **buff系统**：给角色添加一个的buff系统，buff效果，buff持续时间等
* **队伍系统**：可以制作一个团队系统，在游戏中可以切换队员
* **地图指引**：可以做一个小地图，或者在场景中做一些场景提示
* **传送系统**：做一些传送点**（荐）**
* **破坏地形**：可以制作一些可破坏的地形 / 背景
* **材质Shader**：动态灯光，屏幕受伤红光效果，物品局部发光效果；自制材质球，设置 Shader 赋值给模型
* **更生动的场景**：可以考虑给场景的物体加一些动画
* **更精细的敌人AI系统**：范围巡逻，追击，脱离范围后的返回，攻击连招，攻击衔接，受伤打断等等等
* **对话系统**：写一个可配置，可拓展的对话系统，**数据与逻辑分离**，可通过 **Excel 表格、Word文档**等方式进行外部数据读取，从而更方便快捷的更改对话内容**（荐）**
* **商店系统**：可通过金币来购买物品 / 技能 / 属性等
* **算法嵌入**：可使用各类寻路算法（A* 、Dijkstra等），柏林噪声算法，随机生成地牢等算法进行代码优化
* **其他** ：写一些小的工具类，比如 Timer 计时器类，泛型 Singleton ，字符串变量化类，Helper类，Param类等等
* **最后，发挥想象力实现更多创意功能.....**
