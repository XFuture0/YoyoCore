<b><size=20>输入管理器</size></b>

<i>处理输入这件事，说简单也简单，说复杂……咳咳，等你需要支持手柄、触屏、键盘的时候就知道复杂了。</i>

InputMgr 提供了一个统一的输入管理方案，将输入检测与事件系统结合，让输入处理变得更加优雅。

<b><size=16>诞生背景</size></b>

传统的 Unity 输入处理通常是这样的：

void Update()
{
    if (Input.GetKeyDown(KeyCode.Space))
    {
        Jump();
    }
    if (Input.GetKeyDown(KeyCode.Escape))
    {
        Pause();
    }
    // ... 更多的输入检测
}

这种方式的问题是：
1. 输入检测散落在各个类的 Update 中，难以统一管理
2. 键位硬编码，修改键位需要改代码
3. 无法方便地启用/禁用输入
4. 输入逻辑和业务逻辑耦合

InputMgr 通过「事件绑定」的方式解决了这些问题。

<b><size=16>核心概念</size></b>

InputMgr 使用 InputInfo 类来描述一个输入配置：

public class InputInfo
{
    public E_KeyOrMouse KeyOrMouse;  // 键盘还是鼠标
    public E_InputType InputType;    // 按下、抬起还是持续按下
    public KeyCode KeyCode;          // 按键代码
    public int MouseCode;            // 鼠标按钮代码
}

输入类型（E_InputType）：

<b>类型：Down</b>
说明：按键按下的瞬间触发一次

<b>类型：Up</b>
说明：按键抬起的瞬间触发一次

<b>类型：Press</b>
说明：按键持续按下时每帧都触发

<b><size=16>使用方法</size></b>

<b>绑定键盘输入</b>

// 绑定空格键按下事件
InputMgr.Instance.AddKeyBoardInfo(
    EventType.Jump,           // 事件类型
    KeyCode.Space,            // 按键
    InputInfo.E_InputType.Down, // 触发时机
    Jump                      // 回调函数
);

void Jump()
{
    Debug.Log("跳跃！");
}

<b>绑定鼠标输入</b>

// 绑定鼠标左键按下事件
InputMgr.Instance.AddMouseInfo(
    EventType.Fire,
    0,                        // 0=左键, 1=右键, 2=中键
    InputInfo.E_InputType.Down,
    Fire
);

void Fire()
{
    Debug.Log("开火！");
}

<b>移除输入绑定</b>

InputMgr.Instance.RemoveInputInfo(EventType.Jump);

<b>启用/禁用输入</b>

// 关闭输入检测
InputMgr.Instance.StartOrCloseInput(false);

// 开启输入检测
InputMgr.Instance.StartOrCloseInput(true);

<b><size=16>完整示例</size></b>

public class PlayerController : MonoBehaviour
{
    void Start()
    {
        // 绑定移动输入
        InputMgr.Instance.AddKeyBoardInfo(
            EventType.MoveLeft,
            KeyCode.A,
            InputInfo.E_InputType.Press,
            () => Move(Vector3.left)
        );

        InputMgr.Instance.AddKeyBoardInfo(
            EventType.MoveRight,
            KeyCode.D,
            InputInfo.E_InputType.Press,
            () => Move(Vector3.right)
        );

        // 绑定跳跃输入
        InputMgr.Instance.AddKeyBoardInfo(
            EventType.Jump,
            KeyCode.Space,
            InputInfo.E_InputType.Down,
            Jump
        );

        // 绑定攻击输入
        InputMgr.Instance.AddMouseInfo(
            EventType.Attack,
            0,
            InputInfo.E_InputType.Down,
            Attack
        );
    }

    void OnDestroy()
    {
        // 清理输入绑定
        InputMgr.Instance.RemoveInputInfo(EventType.MoveLeft);
        InputMgr.Instance.RemoveInputInfo(EventType.MoveRight);
        InputMgr.Instance.RemoveInputInfo(EventType.Jump);
        InputMgr.Instance.RemoveInputInfo(EventType.Attack);
    }

    void Move(Vector3 dir)
    {
        transform.position += dir * Time.deltaTime * speed;
    }

    void Jump()
    {
        rb.AddForce(Vector3.up * jumpForce);
    }

    void Attack()
    {
        // 攻击逻辑
    }
}

<b><size=16>技术实现</size></b>

InputMgr 在构造函数中订阅了 MonoMgr 的 Update：

private InputMgr()
{
    MonoMgr.Instance.AddUpdateListener(Update);
}

在 Update 中轮询所有绑定的输入。

<b><size=16>注意事项</size></b>

<b>1. 事件定义</b>

所有输入都会触发 EventType 对应的事件，所以你需要先在 EventEnums.cs 中定义好相关事件。

<b>2. 输入冲突</b>

同一个 EventType 只能绑定一个输入配置。如果重复绑定，后面的会覆盖前面的。

<b>3. 清理绑定</b>

记得在对象销毁时清理输入绑定，否则会造成内存泄漏。

<b><size=16>适用场景</size></b>

<b>场景：角色移动控制</b>
是否适合：适合

<b>场景：UI 快捷键</b>
是否适合：适合

<b>场景：需要频繁变更键位的游戏</b>
是否适合：适合

<b>场景：需要动态启用/禁用的输入</b>
是否适合：适合

<b>场景：需要组合键检测</b>
是否适合：不适合（需自行扩展）

<b><size=16>与 Unity Input System 的对比</size></b>

<b>特性：学习成本</b>
InputMgr：低
Unity Input System：较高

<b>特性：功能丰富度</b>
InputMgr：基础
Unity Input System：丰富（支持手柄、触屏等）

<b>特性：与事件系统集成</b>
InputMgr：内置
Unity Input System：需自行封装

<b>特性：适用项目规模</b>
InputMgr：中小型
Unity Input System：中大型

<b><size=16>技术地位和意义</size></b>

InputMgr 是框架中负责「人机交互」的入口。它将输入检测与业务逻辑解耦，让输入配置更加灵活。对于中小型项目来说，它提供了一个轻量级但功能完整的输入解决方案。

<i>当然，如果你的项目需要支持多平台、多种输入设备，可能需要考虑 Unity 的 Input System 或者 Rewired 这样的专业插件。</i>
