# 资源加载

*Resources.Load 很简单，但简单的工具往往需要更多的封装才能用得舒服。*

LoadResourceMgr 封装了 Unity 的 Resources 系统，提供了同步和异步两种加载方式，以及资源卸载功能。

## 诞生背景

Unity 原生的 Resources.Load 虽然简单，但在实际项目中直接使用会有一些问题：

1. **路径问题**：路径写错只能在运行时才发现
2. **异步加载繁琐**：需要使用 ResourceRequest 和协程
3. **资源管理混乱**：加载的资源不知道什么时候该卸载

LoadResourceMgr 通过封装解决了这些问题。

## 核心功能

**同步加载**

最简单的加载方式，会阻塞主线程直到加载完成：

```csharp
GameObject prefab = LoadResourceMgr.Instance.Load<GameObject>("Prefabs/Player");
GameObject player = Instantiate(prefab);
```

同步加载适用于：
- 资源较小，加载时间可接受
- 必须在当前帧完成加载的场景
- 初始化阶段预加载资源

**异步加载**

不会阻塞主线程，加载完成后通过回调通知：

```csharp
LoadResourceMgr.Instance.LoadAsync<GameObject>("Prefabs/Enemy", (prefab) =>
{
    GameObject enemy = Instantiate(prefab);
});
```

异步加载适用于：
- 资源较大，加载时间较长
- 运行时动态加载
- 需要显示加载进度条的场景

**卸载资源**

```csharp
// 卸载特定资源
LoadResourceMgr.Instance.UnLoadAsset(prefab);

// 卸载所有未使用的资源
LoadResourceMgr.Instance.Clear(() =>
{
    Debug.Log("资源清理完成");
});
```

## 使用方法

**基本加载**

```csharp
public class GameManager : MonoBehaviour
{
    void Start()
    {
        // 同步加载玩家预制体
        GameObject playerPrefab = LoadResourceMgr.Instance.Load<GameObject>("Prefabs/Player");
        Instantiate(playerPrefab);

        // 异步加载关卡
        LoadResourceMgr.Instance.LoadAsync<GameObject>("Maps/Level1", OnLevelLoaded);
    }

    void OnLevelLoaded(GameObject levelPrefab)
    {
        Instantiate(levelPrefab);
    }
}
```

**加载不同类型的资源**

```csharp
// 加载贴图
Texture2D texture = LoadResourceMgr.Instance.Load<Texture2D>("Textures/Background");

// 加载音频
AudioClip clip = LoadResourceMgr.Instance.Load<AudioClip>("Music/BGM");

// 加载材质
Material mat = LoadResourceMgr.Instance.Load<Material>("Materials/Glow");
```

## 技术细节

**路径检查**

LoadResourceMgr 在加载前会检查文件是否存在。

**异步加载实现**

异步加载使用协程实现：

```csharp
private IEnumerator ReallyLoadAsync<T>(string path, UnityAction<T> callback) where T : UnityEngine.Object
{
    ResourceRequest rq = Resources.LoadAsync<T>(path);
    yield return rq;  // 等待加载完成
    callback?.Invoke(rq.asset as T);
}
```

**资源命名**

加载的资源会自动添加 "(res)" 后缀，便于调试识别。

## 注意事项

**1. Resources 文件夹的限制**

Resources 系统有一些限制：
- 所有 Resources 文件夹下的资源都会被打包，无法通过 AssetBundle 单独管理
- Resources 文件夹不宜过大，会影响启动时间和内存占用
- 对于大型项目，建议使用 AssetBundle 或 Addressables

**2. 资源卸载**

Resources.UnloadAsset 只能卸载非 GameObject 资源（如 Texture、AudioClip）。GameObject 资源需要通过 Destroy 销毁实例，然后调用 Resources.UnloadUnusedAssets 清理。

**3. 异步加载的回调时机**

异步加载的回调可能在下一帧或更晚执行，注意处理时序问题。

## 适用场景

**场景：小型项目/原型开发**
推荐方式：Resources + LoadResourceMgr

**场景：需要动态下载资源**
推荐方式：AssetBundle

**场景：大型项目/多平台**
推荐方式：Addressables

**场景：需要精细控制内存**
推荐方式：AssetBundle/Addressables

## 技术地位和意义

LoadResourceMgr 是框架中负责「资源供给」的组件。它简化了 Resources 系统的使用，让开发者可以更专注于游戏逻辑。对于中小型项目来说，它是一个轻量级且功能完整的资源加载方案。

*当然，随着项目规模增长，你可能需要迁移到 Addressables。但在此之前，LoadResourceMgr 已经能满足大部分需求了。*
